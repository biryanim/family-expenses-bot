# family-expenses-bot

Сервис учёта семейных расходов: Telegram-бот с ИИ-агентом и REST API для веб-панели главы семьи.

Член семьи пишет боту обычным текстом: «кофе 350», «такси 1200 вчера», «сколько потратил на еду в этом месяце», «удали такси». Агент через tool calling добавляет, показывает, изменяет и удаляет траты. Кнопок и команд нет. Каждый пользователь видит и меняет только свои траты.

## Запуск

```sh
cp .env.example .env
docker compose up --build
```

В `.env` нужно заполнить `TELEGRAM_BOT_TOKEN`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL` и пароль PostgreSQL в `POSTGRES_PASSWORD` и `DATABASE_DSN`. Подойдёт любой OpenAI-совместимый Chat Completions API с поддержкой tool calling. Миграции применяет сервис `migrate` до старта приложения. REST API слушает `HTTP_PORT` (по умолчанию 8080), веб-панель доступна на `http://localhost:3000` (порт `WEB_PORT`) и обращается к API через собственный `/api/`. Если пароль PostgreSQL содержит `@ : / ?` и подобные символы, в `DATABASE_DSN` его нужно URL-кодировать (или взять пароль попроще).

`GET /api/expenses` отдаёт траты постранично: параметры `limit` (1–500, по умолчанию 100) и `offset`, общее количество подходящих трат приходит в заголовке `X-Total-Count`.

Данные БД лежат в томе `pgdata` и переживают `docker compose down`. Чтобы стереть их, выполните `docker compose down -v`.

Остальные команды (`make test`, `make lint`, `make migrate-*`) описаны в `Makefile`.

## Неоднозначные случаи

Если запрос можно понять по-разному, бот переспрашивает. Необратимых действий (удаление, изменение) наугад он не выполняет.

- **«Последнее»** — последняя *созданная* трата пользователя, независимо от даты траты. «Удали последнее» после «такси 1200», а затем «кофе 350 вчера» удалит кофе.
- **Несколько совпадений** («удали такси», а такси два). Бот ничего не удаляет и не меняет. Он перечисляет варианты с суммой и датой и спрашивает, какой выбрать. На ответ «второе» или «то, что за 500» удаляется выбранная трата. Если выбор всё ещё неясен, бот спросит снова.
- **Нет суммы** («кофе»). Трата не добавляется, бот спрашивает сумму. Ответ «350» добавит «кофе 350».
- **Нет подходящей траты для изменения или удаления.** Бот отвечает, что такой траты не нашёл. Ничего не меняется и ничего нового не добавляется.
- **Нераспознанная дата** («кофе 350 на днях»). Трата записывается **на сегодня**, и бот предупреждает об этом в ответе. Добавление обратимо, поэтому лишний круг вопросов не нужен. Дату можно поправить следующим сообщением: «последнее было вчера» или «последнее было 15 октября». Понятные относительные даты («вчера», «позавчера», «в понедельник») бот считает от текущей даты.
- **Сообщение не про расходы** («расскажи анекдот»). Бот вежливо и коротко отвечает, что умеет, и не трогает траты.

### Короткая память диалога

Чтобы понимать ответы на уточнения, бот помнит последние 6 реплик с каждым пользователем: его сообщения и свои ответы. Реплики старше 15 минут забываются. Память хранится в процессе приложения и пропадает при перезапуске. Тогда бот просто переспросит, ничего не удалив. История каждого пользователя отдельная, чужие реплики в неё не попадают.

## Веб-панель

Панель главы семьи: траты всех членов семьи с фильтрами по члену семьи, периоду и категории, создание, правка и удаление. Работает через REST API, авторизации нет.

Локальный запуск при запущенном бэкенде (`make run`):

```
npm --prefix web ci
npm --prefix web run dev
```

Панель откроется на `http://localhost:5173`, запросы к `/api` проксируются на бэкенд.

Переменные (см. `web/.env.example`):

- `VITE_API_BASE_URL` — базовый адрес API при сборке, по умолчанию `/api`.
- `VITE_API_PROXY_TARGET` — куда dev-сервер проксирует `/api`, по умолчанию `http://localhost:8080` (`web/.env.development`).
- `API_UPSTREAM` — адрес бэкенда для nginx в образе панели, задаётся при запуске контейнера, по умолчанию `http://app:8080`.

После правки `api/openapi.yaml` TypeScript-типы пересоздаются командой `make generate-web`.

Образ панели: `docker build -t family-expenses-web web/`. В `docker compose` панель подключена сервисом `web`.

Даты и периоды в панели считаются в часовом поясе браузера, а «сегодня» и «вчера» в боте — в часовом поясе контейнера (`TZ`). Если пояса различаются, на границе суток день в фильтре и в боте может не совпасть.
