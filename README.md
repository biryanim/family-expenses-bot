# family-expenses-bot

Сервис учёта семейных расходов. Члены семьи записывают траты обычным текстом в Telegram-боте, а глава семьи видит и правит траты всех в веб-панели.

- **Telegram-бот с ИИ-агентом.** Пишешь «кофе 350», бот сам определяет сумму, категорию и дату и сохраняет трату. Так же текстом траты можно посмотреть, изменить и удалить. Кнопок и команд нет. Каждый член семьи видит и меняет только свои траты.
- **Веб-панель главы семьи.** Траты всех членов семьи с фильтрами по члену семьи, периоду и категории, постраничный список, создание, правка и удаление. Работает через REST API, авторизации нет.

## Быстрый старт

Нужны Docker с Compose, токен бота от [@BotFather](https://t.me/BotFather) и доступ к любому OpenAI-совместимому Chat Completions API с поддержкой tool calling.

```sh
cp .env.example .env
# заполнить TELEGRAM_BOT_TOKEN, LLM_BASE_URL, LLM_API_KEY, LLM_MODEL и пароль PostgreSQL
docker compose up --build
```

После старта:

- бот отвечает в Telegram;
- веб-панель открывается на <http://localhost:3000>;
- REST API доступен на <http://localhost:8080/api>.

Compose поднимает сервисы по порядку: `postgres`, затем `migrate` (применяет миграции, когда БД прошла healthcheck), затем `app` (бот и REST API в одном процессе), затем `web` (nginx со статикой панели, проксирует `/api` в `app`).

Данные лежат в томе `pgdata` и переживают `docker compose down`. Чтобы стереть их, выполните `docker compose down -v`.

## Конфигурация

Всё задаётся переменными окружения в `.env`. Шаблон с комментариями лежит в `.env.example`.

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | — | Токен бота |
| `LLM_BASE_URL` | да | — | Адрес OpenAI-совместимого API, например `https://api.openai.com/v1` или `https://openrouter.ai/api/v1` |
| `LLM_API_KEY` | да | — | Ключ API |
| `LLM_MODEL` | да | — | Модель с поддержкой tool calling |
| `LLM_TIMEOUT` | нет | `30s` | Максимальное ожидание одного запроса к модели вместе с ретраями SDK |
| `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB` | да | — | Учётные данные PostgreSQL для сервиса `postgres` |
| `DATABASE_DSN` | да | — | Строка подключения приложения, хост `postgres` |
| `HTTP_PORT` | нет | `8080` | Порт REST API |
| `WEB_PORT` | нет | `3000` | Порт веб-панели на хосте |
| `CORS_ALLOWED_ORIGINS` | нет | `http://localhost:5173` | Источники, которым разрешено ходить в API из браузера (для dev-сервера панели) |
| `LOG_LEVEL` | нет | `info` | `debug`, `info`, `warn`, `error` |
| `TZ` | нет | UTC | Часовой пояс, от которого бот считает «сегодня», «вчера», «в этом месяце» |

Если пароль PostgreSQL содержит `@ : / ?` и подобные символы, в `DATABASE_DSN` его нужно URL-кодировать (или взять пароль попроще).

Скорость ответа бота почти целиком зависит от модели: одно сообщение — это 2–3 последовательных запроса к LLM (вызов инструмента и итоговый ответ). Большие бесплатные модели могут отвечать дольше `LLM_TIMEOUT`. Тогда стоит взять модель быстрее или увеличить таймаут. Проверить, что модель отвечает и умеет tool calling, можно командой `make llm-check`.

## Telegram-бот

Примеры сообщений:

| Действие | Сообщение |
|---|---|
| Добавить | «кофе 350», «такси 1200 вчера», «продукты 2450.50 в понедельник» |
| Посмотреть | «сколько потратил на еду в этом месяце», «покажи траты за неделю» |
| Изменить | «последнее было не 350, а 450», «последнее было вчера» |
| Удалить | «удали такси», «удали последнее» |

Как это устроено:

- Сообщение обрабатывает ИИ-агент. Через tool calling он вызывает инструменты `add_expense`, `list_expenses`, `get_last_expense`, `update_expense`, `delete_expense`. Текущую дату и день недели агент получает в системном промпте, относительные даты считает от них.
- Категории фиксированные: еда, транспорт, жильё, развлечения, здоровье, покупки, другое. Нераспознанная категория становится «другое».
- Итоговую сумму считает база, а не модель. Бот показывает не больше 30 последних трат, но количество и сумма всегда по всем подходящим.
- Сообщения одного пользователя обрабатываются строго по очереди. Сообщения разных пользователей идут параллельно.
- Сообщения длиннее 1000 символов модели не передаются: бот просит их сократить.

### Изоляция трат

`user_id` берётся из Telegram-апдейта и передаётся в инструменты кодом. В схемах инструментов параметра пользователя нет, поэтому модель не может его подставить, даже если её об этом попросить в тексте. Чужая трата для бота неотличима от несуществующей. Это закреплено тестами «пользователь A не видит, не меняет и не удаляет траты B», в том числе через настоящий агент с попытками prompt injection.

### Неоднозначные случаи

Если запрос можно понять по-разному, бот переспрашивает. Необратимых действий (удаление, изменение) наугад он не выполняет.

- **«Последнее»** — последняя *созданная* трата пользователя, независимо от даты траты. «Удали последнее» после «такси 1200», а затем «кофе 350 вчера» удалит кофе.
- **Несколько совпадений** («удали такси», а такси два). Бот ничего не удаляет и не меняет. Он перечисляет варианты с суммой и датой и спрашивает, какой выбрать. На ответ «второе» или «то, что за 500» удаляется выбранная трата. Если выбор всё ещё неясен, бот спросит снова.
- **Нет суммы** («кофе»). Трата не добавляется, бот спрашивает сумму. Ответ «350» добавит «кофе 350».
- **Нет подходящей траты для изменения или удаления.** Бот отвечает, что такой траты не нашёл. Ничего не меняется и ничего нового не добавляется.
- **Нераспознанная дата** («кофе 350 на днях»). Трата записывается **на сегодня**, и бот предупреждает об этом в ответе. Дату можно поправить следующим сообщением: «последнее было вчера» или «последнее было 15 октября».
- **Сообщение не про расходы** («расскажи анекдот»). Бот коротко отвечает, что умеет, и не трогает траты.
- **Модель упала после того, как трата уже записана** (например, таймаут на втором запросе). Бот не пишет «ошибка», а отвечает «Трата на 350 ₽ за 2026-10-21 записана. Подробнее ответить не удалось.». Если повторить то же сообщение, модель видит в истории, что трата уже есть, и не дублирует её.

### Короткая память диалога

Чтобы понимать ответы на уточнения, бот помнит последние 6 реплик с каждым пользователем: его сообщения и свои ответы. Реплики старше 15 минут забываются, а записи ушедших пользователей вычищаются из памяти. Память хранится в процессе приложения и пропадает при перезапуске. Тогда бот просто переспросит, ничего не удалив. История каждого пользователя отдельная.

## Веб-панель

Список трат всех членов семьи, по 50 на страницу, с фильтрами по члену семьи, периоду и категории. Фильтры и номер страницы хранятся в адресе страницы, так что ссылку можно отправить. В панели можно создать, исправить и удалить трату (удаление с подтверждением). Членом семьи считается любой, кто хоть раз писал боту.

Локальный запуск при запущенном бэкенде (`make run`):

```sh
npm --prefix web ci
npm --prefix web run dev
```

Панель откроется на <http://localhost:5173>, запросы к `/api` проксируются на бэкенд.

Переменные панели (см. `web/.env.example`):

- `VITE_API_BASE_URL` — базовый адрес API при сборке, по умолчанию `/api`.
- `VITE_API_PROXY_TARGET` — куда dev-сервер проксирует `/api`, по умолчанию `http://localhost:8080` (`web/.env.development`).
- `API_UPSTREAM` — адрес бэкенда для nginx в образе панели, по умолчанию `http://app:8080`.

Даты и периоды в панели считаются в часовом поясе браузера, а «сегодня» и «вчера» в боте — в часовом поясе контейнера (`TZ`). Если пояса различаются, на границе суток день в фильтре и в боте может не совпасть.

## REST API

Контракт описан в [`api/openapi.yaml`](api/openapi.yaml) (OpenAPI 3.0), все пути с префиксом `/api`.

| Метод | Путь | Что делает |
|---|---|---|
| `GET` | `/expenses` | Список трат. Фильтры `user_id`, `from`, `to` (date-time, `to` не включительно), `category`. Пагинация `limit` (1–500, по умолчанию 100) и `offset`. Общее количество приходит в заголовке `X-Total-Count` |
| `POST` | `/expenses` | Создать трату |
| `GET` | `/expenses/{id}` | Получить трату |
| `PUT` | `/expenses/{id}` | Заменить сумму, категорию, дату и комментарий |
| `DELETE` | `/expenses/{id}` | Удалить трату |
| `GET` | `/members` | Члены семьи |

Сумма `amount` передаётся целым числом копеек: 1200 ₽ — это `120000`. Комментарий не длиннее 200 символов, пробелы по краям обрезаются. Ошибки возвращаются в едином формате `{"code": "...", "message": "..."}`, коды: `invalid_request`, `invalid_amount`, `invalid_category`, `invalid_date`, `invalid_pagination`, `invalid_comment`, `unknown_member`, `not_found`, `internal`. Тело запроса больше 1 МиБ отклоняется.

## Архитектура

Один Go-бинарь: REST API и бот в одном процессе, общая PostgreSQL.

```
Telegram ──► transport/telegram ──► agent ──► agent/tools ─┐
                                      │                     ├──► usecase ──► database/repository ──► PostgreSQL
                                      └──► llm (OpenAI API) │
Браузер ──► nginx (web) ──► transport/http ─────────────────┘
```

- Зависимости направлены внутрь: транспорт и агент → `usecase` → `entity`. Репозиторий реализует интерфейсы, объявленные в `usecase`.
- Бизнес-правила (валидация суммы, категории, даты, комментария, страницы; «последняя трата») живут в `usecase` и общие для бота и REST.
- Деньги хранятся в `int64` копейках, без `float`.
- REST API spec-first: код сервера генерирует `oapi-codegen`, TS-типы панели — `openapi-typescript`, оба из одного `api/openapi.yaml`.

Стек:

- **Бэкенд:** Go 1.27, `chi`, `pgx/v5` с ручным SQL, миграции `goose`, `go-telegram/bot` (long polling), `openai-go/v3`.
- **Фронтенд:** React 19, TypeScript, Vite, TanStack Query, в compose отдаётся через nginx.

## Структура проекта


## Разработка

| Команда | Что делает |
|---|---|
| `make up` / `make down` | Поднять / остановить всё через compose |
| `make run` | Запустить бэкенд локально с переменными из `.env` (нужна доступная БД) |
| `make test` | Go-тесты |
| `make lint` | `golangci-lint` (установка — `make lint-install`) |
| `make check` | Линтер и тесты |
| `make generate` | Сгенерировать сервер из `api/openapi.yaml` и gomock-моки |
| `make generate-web` | Пересоздать TS-типы панели из `api/openapi.yaml` |
| `make llm-check` | Проверить доступ к модели и tool calling |
| `make migrate-up`, `migrate-down`, `migrate-reset`, `migrate-status` | Миграции через сервис `migrate` |
| `make migrate-create name=<имя>` | Создать новую миграцию |
| `npm --prefix web test` | Тесты чистой логики панели (Vitest) |

Порядок изменения API всегда один: правка `api/openapi.yaml` → `make generate` и `make generate-web` → код. Сгенерированные файлы руками не правятся и лежат в репозитории.

В тестах LLM подменяется моком, реальных запросов к провайдеру нет. Сценарии бота (добавление, уточнения, изоляция A/B, prompt injection, сбой модели после записи) проверяются через настоящий агент, инструменты и usecase с замоканным репозиторием.

## Ограничения

- Авторизации в панели нет, так задано в ТЗ. Наружу её открывать нельзя.
- История диалога бота хранится в памяти и не переживает перезапуск.
- Защита от дубля траты при сбое модели мягкая: она опирается на историю диалога и промпт, а не на уникальность в БД.
