# Proposal

## Why

Бот принимает сообщения и регистрирует членов семьи, но отвечает эхом, а LLM-клиент из задачи 07 никто не вызывает. Главный сценарий продукта — «пишешь обычным текстом, бот ведёт траты» — пока не работает. Нужен ИИ-агент, который через tool calling добавляет, показывает, изменяет и удаляет траты пользователя, и его надо подключить к боту вместо эха.

## What Changes

- Новый цикл агента: на каждое текстовое сообщение собирается системный промпт (роль, фиксированные категории, текущая дата с днём недели, правила коротких ответов), модель вызывает инструменты, их результаты возвращаются модели, финальный текст модели уходит пользователю. Шагов не больше 5 на одно сообщение.
- Инструменты для модели: `add_expense`, `list_expenses` (фильтры: период, категория; в результате — количество и итоговая сумма, посчитанные кодом), `get_last_expense`, `update_expense` (частичное изменение по `id`), `delete_expense` (по `id`). В схемах инструментов нет параметра пользователя: `user_id` из Telegram-апдейта передаётся в инструменты кодом.
- Сумма приходит от модели в рублях (до копеек) и переводится в копейки разбором строки, без float. Категория вне списка при добавлении и изменении заменяется на «другое». Дата без указания — сегодня, относительные даты модель считает от даты из промпта.
- Память диалога не хранится: каждое сообщение обрабатывается независимо. «Последняя трата» — последняя добавленная трата пользователя, её отдаёт отдельный инструмент. Если по описанию («удали такси») подходит несколько трат, изменяется или удаляется самая поздняя по дате, и бот называет в ответе, какую именно.
- Usecase получает операции в пределах одного члена семьи (`GetExpenseForUser`, `ListExpensesForUser`, `UpdateExpenseForUser`, `DeleteExpenseForUser`) с теми же правилами валидации, что у общих, и `GetLastExpenseForUser`. Репозиторий — `GetLastExpenseForUser`.
- **BREAKING (поведение бота):** эхо-ответ удаляется, бот отвечает текстом агента. Если агент не справился (LLM недоступна, таймаут, превышен лимит шагов, сбой БД), бот отвечает коротким сообщением о временной ошибке, а ошибка пишется в лог.
- Часовой пояс для «сегодня/вчера/этот месяц» задаётся стандартной переменной `TZ` (в `.env.example` — `Europe/Moscow`). Без неё контейнер работает в UTC, и ночью по Москве даты съезжают на день.

## Capabilities

### New Capabilities
- `expense-agent`: ИИ-агент учёта трат — системный промпт, набор инструментов и их схемы, цикл вызовов, разбор суммы, категории и даты, правила «последней траты» и выбора траты по описанию, формат ответов, изоляция пользователя в инструментах.

### Modified Capabilities
- `telegram-bot`: эхо заменяется ответом агента; при ошибке агента — сообщение о временной ошибке.
- `expense-rules`: правила суммы, категории и даты действуют и для операций в пределах одного члена семьи; добавляется правило «последняя трата».
- `expense-repository`: добавляется получение последней добавленной траты члена семьи.
- `app-bootstrap`: часовой пояс приложения задаётся `TZ`.

## Impact

- Код: `internal/agent/*` (цикл, `deps.go` с новыми интерфейсами), новый пакет `internal/agent/tools/*` (инструменты), `internal/usecase/*` (пять новых методов, `deps.go`), `internal/database/repository/get_last_expense_for_user.go`, `internal/entity/amount.go` (разбор и форматирование суммы), `internal/transport/telegram/*` (вызов агента вместо эха), `cmd/app/main.go` (сборка агента), `mock/*` (новые и перегенерированные моки).
- Конфиг: `.env.example` получает `TZ=Europe/Moscow`. Новых `LLM_*` переменных нет.
- Зависимости, REST API, схема БД, миграции: без изменений.
- Не входит: память диалога и уточняющие вопросы с продолжением, индикатор «печатает…», голосовые и фото чеков, общий таймаут на всё сообщение сверх `LLM_TIMEOUT` на каждый вызов, учёт токенов.
