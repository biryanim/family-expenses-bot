# Proposal

## Why

Бэкенд уже отдаёт REST API для веб-панели, но самой панели нет: `web/` пустой. Главе семьи нечем смотреть траты всех членов семьи и править их. Задачи 11–13 вместе дают рабочую панель: каркас, список с фильтрами и операции создания, правки и удаления. Они делаются одним изменением, потому что по отдельности ни одна не даёт законченного поведения: каркас без списка ничего не показывает, а правка без списка негде вызвать.

## What Changes

- **Проект фронтенда в `web/`.** React + Vite + TypeScript, запросы через TanStack Query. Авторизации нет.
- **TS-типы API генерируются** из `api/openapi.yaml` через `openapi-typescript` скриптом в `package.json` и коммитятся. Руками типы API не пишутся. Типизированный клиент строится на сгенерированных типах.
- **Адрес API не зашит в код.** Фронтенд ходит по базовому пути из переменной сборки `VITE_API_BASE_URL` (по умолчанию `/api`, как `servers.url` в спецификации). В dev-режиме Vite проксирует `/api` на бэкенд, адрес которого берётся из переменной окружения. В образе nginx проксирует `/api` на upstream из переменной окружения контейнера. Браузер работает с одним origin, CORS в этой схеме не нужен.
- **Dockerfile в `web/`.** Multi-stage: сборка статики на Node, отдача через nginx с проксированием `/api`. В `docker-compose.yml` сервис подключается в задаче 14, не здесь.
- **Список трат всех членов семьи.** Таблица: владелец (имя из `GET /members`), сумма в рублях, категория по-русски, дата, комментарий. Фильтры по члену семьи, периоду и категории работают в комбинации и передаются в `GET /expenses` как query-параметры. Состояния: загрузка, пусто, ошибка.
- **Создание, правка, удаление.** Форма создания (владелец, сумма, категория, дата, комментарий), форма правки (владелец только для чтения, API не позволяет его менять), удаление с подтверждением. Валидация на форме и показ ошибок API. После операции список перезапрашивается с текущими фильтрами.
- **Деньги без float.** Ввод «350,50» разбирается в копейки строковыми операциями, вывод копеек — целочисленным делением.
- **Команда генерации.** `make generate-web` запускает генерацию TS-типов. `make generate` не меняется и остаётся равным `go generate ./...`, чтобы Go-генерация не требовала Node.

## Capabilities

### New Capabilities

- `web-panel`: веб-панель главы семьи — конфигурация адреса API, отдача статики, список трат с фильтрами, создание, правка и удаление трат, отображение денег, дат и ошибок.

### Modified Capabilities

- `api-codegen`: добавляется требование о генерации TS-типов фронтенда из той же спецификации, их коммите и проверке, что сборка фронтенда генератор не запускает.

## Impact

- Новый каталог `web/`: `package.json`, `package-lock.json`, `vite.config.ts`, `tsconfig*.json`, `index.html`, `src/`, `Dockerfile`, `nginx/default.conf.template`, `.dockerignore`, `.env.example`.
- Новые npm-зависимости: `react`, `react-dom`, `@tanstack/react-query`, `openapi-fetch`; dev — `vite`, `@vitejs/plugin-react`, `typescript`, `openapi-typescript`, `vitest`. Зачем нужны `openapi-fetch` и `vitest` — в design.md.
- `Makefile`: цель `generate-web`.
- `README.md`: раздел о запуске панели локально.
- Go-код, `api/openapi.yaml`, схема БД и `docker-compose.yml` не меняются. Подключение панели в compose — задача 14.
- `CORS_ALLOWED_ORIGINS` остаётся для случая, когда панель открыта с другого origin без прокси. В основной схеме он не используется.
