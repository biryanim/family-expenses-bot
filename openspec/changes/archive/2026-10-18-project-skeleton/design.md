# Design

## Context

Мотивация — см. proposal.md. В репозитории есть `go.mod` (Go 1.27.0) без зависимостей, `AGENTS.md` с целевой структурой и стеком, и пустой OpenSpec. Требования к поведению — в `specs/app-bootstrap/spec.md`.

## Goals / Non-Goals

**Goals:**
- Зафиксировать структуру пакетов, чтобы следующие изменения только добавляли код в готовые места.
- Единственная точка сборки зависимостей — `cmd/app/main.go`.
- Ошибка конфигурации обнаруживается при старте целиком, а не по одной переменной за запуск.

**Non-Goals:**
- HTTP-сервер, подключение к БД, миграции, бот, LLM-клиент — каждый появится в своём изменении.
- Проверка доступности внешних систем (БД, LLM, Telegram) при старте: на этом шаге проверяется только наличие и формат значений.
- Загрузка `.env` самим приложением: файл читает `docker compose`, локально — shell.

## Decisions

### Конфиг: стандартная библиотека, без `caarlos0/env`/`viper`
Пять обязательных строк и два необязательных значения — `os.Getenv` + `strconv` хватает. Внешняя библиотека не входит в стек `AGENTS.md`, а выигрыш на таком объёме нулевой.

Форма: `config.Load() (Config, error)` возвращает плоскую структуру с вложенными группами (`Telegram`, `LLM`, `DB`, `HTTP`, `Log`). Чтобы тестировать без глобального окружения, внутри — `load(getenv func(string) string)`, а `Load` передаёт `os.Getenv`. Тесты используют `t.Setenv` или подставную функцию; table-driven.

Ошибки копятся и объединяются через `errors.Join`, плюс сводная ошибка вида `missing required env: LLM_API_KEY, DATABASE_URL`. Альтернатива «падать на первой» отвергнута — спека требует перечислить все.

`HTTP_PORT` хранится как `int` (проверка диапазона), адрес `:<port>` собирается там, где поднимается сервер. `LOG_LEVEL` парсится в `slog.Level`.

Имена переменных: `TELEGRAM_BOT_TOKEN`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `DATABASE_URL`, `HTTP_PORT`, `LOG_LEVEL` — общепринятые, совпадают с тем, что ждут docker-образы и туториалы.

### Секреты в `Config`
Чтобы случайный `slog.Any("config", cfg)` не слил токены, у `Config` реализуется `LogValue() slog.Value`, отдающий только несекретные поля. Это дешёвая страховка под требование «секреты не попадают в логи».

### Логирование: `log/slog` с `JSONHandler` в stdout
Стандартная библиотека, структурированный вывод, уровни — то, что нужно; `zap`/`zerolog` не дают выгоды при нашей нагрузке. Логгер создаётся в `main` и передаётся в зависимости явно; дополнительно ставится `slog.SetDefault`, чтобы сторонние библиотеки, пишущие через `slog`, попадали в тот же поток.

Ошибку загрузки конфига `main` пишет до создания настроенного логгера: в stderr через `fmt.Fprintln` и `os.Exit(1)`. Так ошибка видна даже при битом `LOG_LEVEL`.

### Жизненный цикл в `main`
`signal.NotifyContext(ctx, SIGINT, SIGTERM)` → лог старта → `<-ctx.Done()` → лог остановки → выход 0. Логика вынесена в `run(ctx, ...) error`, `main` только вызывает её и переводит ошибку в код выхода — так в следующих изменениях сюда добавляются HTTP-сервер и бот (например, через `errgroup`) без переписывания `main`.

### Docker
- `Dockerfile`: multi-stage — `golang:1.27` собирает статический бинарь (`CGO_ENABLED=0`), финальный образ `gcr.io/distroless/static-debian12:nonroot` (минимальный, без shell, не root). Альтернатива `alpine` — больше поверхность, а shell в рантайме не нужен.
- `docker-compose.yml`: сервисы `postgres` (`postgres:17-alpine`, volume, healthcheck `pg_isready`) и `app` (`build: .`, `env_file: .env`, `depends_on: postgres: condition: service_healthy`, проброс `HTTP_PORT`). `DATABASE_URL` в `.env.example` указывает на хост `postgres` внутри сети compose. Фронтенд/nginx добавятся отдельным изменением.

### Пустые папки и `api/openapi.yaml`
Папки без кода получают `.gitkeep`; когда в папке появляется первый файл, `.gitkeep` удаляется. `api/openapi.yaml` — валидный OpenAPI 3.0 с `info` и пустым `paths: {}`, чтобы последующие изменения дописывали эндпоинты, а не создавали файл.

### Зависимости в `go.mod`
Сейчас не добавляются: `go mod tidy` выкинет неиспользуемые модули, а пустые импорты ради «зафиксировать стек» — шум. Каждая библиотека из `AGENTS.md` придёт с кодом, который её использует.

## Risks / Trade-offs

- [Версии образов `golang:1.27`/`postgres:17-alpine` могут оказаться недоступны или устареть] → при реализации проверить, что тег существует (`docker pull`), и при необходимости взять ближайший актуальный; версия Go в образе должна быть не ниже версии из `go.mod`.
- [`.env` с реальными секретами случайно попадёт в git] → `.env` в `.gitignore`, в `.env.example` только плейсхолдеры; перед коммитом проверить `git status`.
- [Приложение «ничего не делает», и `docker compose up` выглядит как зависший процесс] → стартовая запись в лог явно сообщает, что приложение запущено и ждёт сигнала; это ожидаемо для каркаса.
- [distroless без shell неудобен для отладки внутри контейнера] → для отладки можно временно собрать с `:debug`-тегом; в рабочем образе shell не нужен.
