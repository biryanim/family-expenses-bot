# Design

## Context

Уже есть (проверено по коду): `Dockerfile` с таргетами `migrate` (goose, distroless), `build` и финальным образом приложения; `web/Dockerfile` (node → nginx, шаблон `web/nginx/default.conf.template` с `API_UPSTREAM`); `docker-compose.yml` с `postgres` (healthcheck, том `pgdata`), `migrate` (после healthy БД, `restart: "no"`) и `app` (после `service_completed_successfully`). `.dockerignore` исключает `.env`. Не хватает сервиса `web`, `WEB_PORT`, README-сценария и самой проверки «с нуля». Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:**
- Один `docker compose up --build` поднимает БД, миграции, приложение и панель.
- Панель работает через nginx на одном origin с `/api/`, без CORS и без пересборки при смене адреса API.

**Non-Goals:**
- Healthcheck `app` (distroless без shell/wget; встроенный health-эндпоинт потребовал бы кода и правки API).
- Устранение дублирования пароля в `POSTGRES_PASSWORD` и `DATABASE_DSN`: `DATABASE_DSN` нужен и для `make run` (на локальной машине), поэтому остаётся отдельной переменной.
- Прод-развёртывание: TLS, внешний proxy, registry, CI.

## Decisions

1. **`web` стартует после `app` с `condition: service_started`.** Healthcheck у `app` нет, а nginx резолвит имя `app` при старте, и для этого достаточно созданного контейнера; пока `app` поднимается, `/api/` вернёт 502 и заработает сам. Альтернатива — healthcheck через отдельный бинарь в образе: лишний код ради проверки, которая не нужна для критериев.
2. **`API_UPSTREAM: http://app:${HTTP_PORT:-8080}` в `environment` сервиса `web`.** Иначе смена `HTTP_PORT` молча ломает панель, так как значение по умолчанию в образе жёстко `:8080`. Значение по умолчанию в `web/Dockerfile` остаётся для запуска образа отдельно.
3. **Порт панели `${WEB_PORT:-3000}:80`.** 3000 не конфликтует с портом API 8080 и Vite 5173. Порт API на хост тоже публикуется (уже так): нужен для отладки и `make llm-check`-подобных проверок; панели он не нужен.
4. **Панель ходит в `/api` своего origin.** Сборка фронтенда использует `VITE_API_BASE_URL=/api` по умолчанию, поэтому `CORS_ALLOWED_ORIGINS` для compose-сценария не требуется; переменная остаётся для dev-режима Vite.
5. **Существующие образы и сервисы не переписываем.** Альтернатива «единый compose с нуля» только добавила бы риск; критерии закрываются добавлением `web` и сквозной проверкой.
6. **Проверка вручную по чек-листу в tasks.md.** Автотест compose в CI вне объёма; реальный бот требует токена Telegram и LLM-ключа, поэтому проверка «бот+панель на одной БД» делается руками, а сквозной контроль БД и `/api` — через `curl`.

## Risks / Trade-offs

- [Пароль БД с символами `@ : / ?` ломает `DATABASE_DSN`] → в README и `.env.example` указать, что пароль нужно URL-кодировать в DSN или использовать простой.
- [`web` стартовал раньше готовности `app`, первые запросы дают 502] → окно в секунды, панель повторяет запрос по действию пользователя; healthcheck вынесен в non-goals.
- [Часовой пояс `TZ` задан только через `env_file` для `app`] → у distroless образа нет tzdata, если Go не вшивает базу; проверить при apply, что `TZ=Europe/Moscow` реально действует (Go-бинарь импортирует `time/tzdata` или нет), и если нет — зафиксировать в README либо добавить импорт отдельной правкой.
- [Сборка с нуля долгая (Go + npm)] → ожидаемо при первом запуске, слои кешируются.

## Migration Plan

Существующие пользователи: `git pull`, добавить `WEB_PORT` в `.env` (необязательно), `docker compose up --build`. Данные в `pgdata` сохраняются. Откат — убрать сервис `web` из compose, остальное не затронуто.
