# Proposal

## Why

Следующий шаг бота — ИИ-агент, который через tool calling добавляет и меняет траты. Агенту нужен клиент OpenAI-совместимого Chat Completions API, который можно подменить моком в тестах, и который не держит пользователя Telegram в ожидании бесконечно. Сейчас в `internal/llm` и `internal/agent` пусто, конфиг читает `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, но никто их не использует.

## What Changes

- Контракт LLM-клиента объявляется на стороне потребителя, в `internal/agent/deps.go`: один метод «создать chat completion» по истории сообщений и списку инструментов, возвращающий ответ ассистента с текстом и/или разобранными вызовами инструментов. Типы сообщений, инструментов и вызовов — свои, нейтральные к SDK. Мок генерируется `mockgen` в `mock/`.
- Реализация в `internal/llm` на официальном SDK `github.com/openai/openai-go/v3` (новая зависимость): `base_url`, `api_key`, `model` из конфига, ретраи — встроенные в SDK (по умолчанию 2 повтора), своих ретраев и circuit breaker нет.
- Каждый запрос к LLM ограничен таймаутом, общим для всех попыток SDK. Новая необязательная переменная `LLM_TIMEOUT` (длительность Go, по умолчанию `30s`).
- Ошибки провайдера и истёкший таймаут возвращаются как обычные ошибки, обёрнутые именем вызова SDK; таймаут распознаётся через `context.DeadlineExceeded`. Без паники и без утечки ключа.
- Разбор ответа терпим к известным отклонениям совместимых провайдеров (пустые `arguments`).
- Ручная проверка на реальной модели — командой `go run ./cmd/llmcheck` (`make llm-check`): один тестовый инструмент, на выходе разобранный `tool_call`.
- Клиент в `cmd/app/main.go` пока не подключается: его потребитель — агент, он появится в следующем изменении.

## Capabilities

### New Capabilities
- `llm-client`: обращение к OpenAI-совместимой модели с tool calling — выбор провайдера и модели через конфиг, разбор вызовов инструментов, ограничение времени ожидания, поведение при ошибках провайдера.

### Modified Capabilities
- `app-bootstrap`: в список переменных окружения добавляется необязательная `LLM_TIMEOUT` с проверкой значения.

## Impact

- Код: новые `internal/agent/deps.go` и типы сообщений агента, `internal/llm/*`, `cmd/llmcheck/main.go`, `mock/agent.go`; правка `internal/config` (поле `Timeout`, парсинг `LLM_TIMEOUT`), `.env.example`, `Makefile`.
- Зависимости: `github.com/openai/openai-go/v3` в `go.mod`.
- REST API, БД и поведение бота не меняются.
- Для ручной проверки в `.env` нужны настоящие `LLM_API_KEY` и `LLM_MODEL` — сейчас там заглушки.
