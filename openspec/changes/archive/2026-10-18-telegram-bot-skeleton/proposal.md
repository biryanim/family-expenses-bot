# Proposal

## Why

REST API и общий слой `usecase` готовы, но второй вход в систему — Telegram-бот — отсутствует: `internal/transport/telegram` пуст, а члены семьи в таблицу `users` ниоткуда не попадают. Из-за внешнего ключа `expenses.user_id → users.telegram_id` трату нельзя создать ни через бота, ни через панель, пока пользователь не записан. Нужен каркас бота, на который следующие задачи (клиент LLM, агент с инструментами) навесят обработку трат.

## What Changes

- Подключается `github.com/go-telegram/bot`: приложение в том же процессе, что и HTTP-сервер, получает обновления через long polling и отвечает в чат.
- Обрабатываются только текстовые сообщения. `user_id` берётся кодом из `message.from.id` апдейта и передаётся дальше в обработчик; модель и текст сообщения на него не влияют.
- Отправитель при каждом текстовом сообщении записывается как член семьи (создаётся при первом сообщении, профиль из Telegram — username, имя, фамилия — обновляется при последующих).
- Временный ответ — эхо текста сообщения. Его заменит ответ агента в задаче 08.
- Ни кнопок, ни команд: `/start` и любой другой текст обрабатываются одинаково, как обычный текст. Нетекстовые сообщения получают короткую подсказку, что бот понимает только текст.
- Ошибки обработки сообщения (сбой БД, сбой отправки ответа, паника в обработчике) логируются и не роняют процесс; бот продолжает принимать сообщения.
- Старт: при невалидном токене приложение завершается с ошибкой до начала работы. Остановка по `SIGINT`/`SIGTERM` останавливает и long polling, и HTTP-сервер.
- Репозиторий: новая операция «сохранить члена семьи» (вставка или обновление профиля по Telegram ID). Usecase: `RegisterMember`.

## Capabilities

### New Capabilities
- `telegram-bot`: приём сообщений бота через long polling, определение `user_id` из апдейта, регистрация отправителя как члена семьи, ответ в чат, устойчивость к ошибкам обработки.

### Modified Capabilities
- `expense-repository`: добавляется сохранение члена семьи (создание или обновление профиля по Telegram ID).
- `app-bootstrap`: приложение запускает бота после подключения к БД, завершается с ошибкой при невалидном токене и останавливает бота вместе с HTTP-сервером.

## Impact

- Код: `internal/transport/telegram/*` (новый пакет: обработчик, `deps.go`, тесты), `internal/usecase/register_member.go` + тест, `internal/usecase/deps.go`, `internal/database/repository/upsert_user.go` + тест, `cmd/app/main.go`, `mock/*` (новый `mock/telegram.go`, перегенерация `mock/usecase.go`).
- Зависимости: `github.com/go-telegram/bot` v1.27.0 — уже зафиксирован в стеке `AGENTS.md`.
- Конфиг: без изменений, `TELEGRAM_BOT_TOKEN` уже обязательный.
- API, схема БД, миграции: без изменений.
- Не входит: LLM-клиент, агент и инструменты для трат (задачи 07–08), webhook-режим, обработка редактирования сообщений, групповые сценарии сверх «ответить в тот же чат».
