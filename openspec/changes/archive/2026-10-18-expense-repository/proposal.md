# Proposal

## Why

Схема трат есть (задача 02), но читать и писать траты из кода пока нечем. REST API, бот и агент (задачи 04–09) опираются на один слой доступа к данным. Его нужно сделать сейчас: с фильтрами для панели, с методами для бота, которые ограничены одним пользователем, и с явной ошибкой «не найдено». Тогда изоляция трат между членами семьи будет заложена на нижнем уровне, а не только в транспорте.

## What Changes

- **BREAKING (внутреннее):** пакет `internal/repository` заменяется на `internal/database` с двумя подпакетами:
  - `internal/database/postgres` — подключение: `Connect(ctx, logger, connString) (*pgxpool.Pool, error)` вместо `repository.NewPool`. После успешного Ping пишет в лог запись об успешном подключении (раньше её писал `main`).
  - `internal/database/repository` — операции над тратами на ручном SQL. Зависимость от БД — интерфейс `Pool` (`Exec`, `Query`, `QueryRow`) в `deps.go`; `*pgxpool.Pool` ему соответствует.
  
  Это отступление от структуры в `AGENTS.md`, поэтому `AGENTS.md` обновляется.
- Интерфейс репозитория трат объявляется в `internal/usecase`. Операции: создать, получить по id, список с фильтрами, изменить, удалить, список известных `user_id`.
- Фильтры списка: член семьи (`user_id`), период по `spent_at` (от включительно, до не включительно, каждая граница необязательна), категория. Фильтры комбинируются по «И».
- Для бота отдельные методы получения, списка, изменения и удаления, где `user_id` — обязательный параметр. Чужая трата для них неотличима от несуществующей.
- Изменение и удаление несуществующей траты возвращают доменную ошибку «трата не найдена». Нарушения ограничений схемы (неизвестный член семьи, сумма ≤ 0, недопустимая категория) превращаются в доменные ошибки.
- Изменение выставляет `updated_at` в текущее время.
- Список известных `user_id` берётся из таблицы членов семьи (`users`), как требует `expense-storage`.
- Тесты — unit-тесты на gomock-моке `Pool` (и моках `pgx.Rows`/`pgx.Row`), без реальной БД: так решил пользователь. Они проверяют SQL и аргументы, сканирование и маппинг ошибок.

## Capabilities

### New Capabilities
- `expense-repository`: слой доступа к тратам. Операции CRUD, фильтры списка, методы с обязательным `user_id` и изоляцией чужих трат, ошибка «не найдено», обновление `updated_at`, список известных `user_id`, доменные ошибки при нарушении ограничений.

### Modified Capabilities
Нет. Поведение `app-bootstrap` (лог об успешном подключении, ошибка без пароля) и инварианты `expense-storage` не меняются.

## Impact

- Код: удаляется `internal/repository/`, появляются `internal/database/postgres/` (`Connect` и перенесённый тест «пароль не утекает») и `internal/database/repository/` (`deps.go`, операции над тратами, моки, тесты). Новые файлы: `internal/usecase/` (интерфейс репозитория), `internal/entity/` (фильтр списка, доменные ошибки). В `cmd/app/main.go` вызов `repository.NewPool` меняется на `postgres.Connect`.
- Зависимости: `go.uber.org/mock` (gomock, mockgen) — только для тестов и генерации моков.
- `AGENTS.md`: структура каталогов и правила зависимостей (`repository` → `database/repository`).
- Вне скоупа: upsert и чтение профилей членов семьи (задача 06), бизнес-валидация, «нераспознанная категория → другое», дата по умолчанию и «последняя трата» в `usecase` (задачи 08/09), пагинация, подключение репозитория в `main` (появится вместе с первым потребителем).
