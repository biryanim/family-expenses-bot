# Spec Delta

## MODIFIED Requirements

### Requirement: Список трат с фильтрами
Слой доступа SHALL возвращать страницу трат, отфильтрованных по любой комбинации условий: член семьи, начало периода (включительно), конец периода (не включительно) по `spent_at`, категория. Не заданное условие не ограничивает выборку. Условия объединяются по «И». Порядок — от новых `spent_at` к старым, при равном `spent_at` — от большего `id` к меньшему. Пустой результат — пустая страница с нулевыми количеством и суммой, не ошибка.

#### Scenario: Без фильтров
- **WHEN** список запрашивается без условий
- **THEN** возвращаются траты всех членов семьи в порядке убывания `spent_at`

#### Scenario: Фильтр по члену семьи
- **WHEN** список запрашивается с условием «член семьи `A`»
- **THEN** возвращаются только траты `A`

#### Scenario: Границы периода
- **WHEN** список запрашивается за период с `2026-10-01T00:00:00+03:00` по `2026-10-08T00:00:00+03:00`
- **THEN** трата ровно в `2026-10-01T00:00:00+03:00` входит в результат, а трата ровно в `2026-10-08T00:00:00+03:00` — нет

#### Scenario: Только одна граница периода
- **WHEN** задано только начало периода (или только конец)
- **THEN** выборка ограничена только с этой стороны

#### Scenario: Фильтр по категории
- **WHEN** список запрашивается с категорией `transport`
- **THEN** возвращаются только траты категории `transport`

#### Scenario: Все фильтры вместе
- **WHEN** заданы член семьи `A`, период и категория `food`
- **THEN** возвращаются только траты `A` категории `food` из этого периода

#### Scenario: Ничего не найдено
- **WHEN** ни одна трата не подходит под условия
- **THEN** возвращается пустая страница, количество `0` и сумма `0`, без ошибки

### Requirement: Изменение траты
Слой доступа SHALL изменять у траты только переданные поля из `amount`, `category`, `spent_at`, `comment` одним атомарным запросом к хранилищу, оставляя непереданные поля без изменений, выставлять `updated_at` в текущее время и возвращать изменённую трату. `id`, `user_id` и `created_at` не меняются. Если траты с таким `id` нет, SHALL возвращаться ошибка «трата не найдена», и ничего не меняется. Два одновременных изменения разных полей одной траты SHALL NOT затирать друг друга.

#### Scenario: Успешное изменение
- **WHEN** у существующей траты меняется сумма на `120000`
- **THEN** возвращается трата с новой суммой и заполненным `updated_at`, а `user_id` и `created_at` прежние

#### Scenario: Повторное изменение
- **WHEN** трата изменяется второй раз
- **THEN** `updated_at` выставляется заново временем этого изменения

#### Scenario: Изменение несуществующей траты
- **WHEN** изменяется трата по `id`, которого нет
- **THEN** возвращается ошибка «трата не найдена»

#### Scenario: Изменение одного поля
- **WHEN** у траты меняется только категория
- **THEN** сумма, дата и комментарий остаются прежними

#### Scenario: Одновременное изменение разных полей
- **WHEN** одновременно меняются сумма траты и её категория двумя независимыми вызовами
- **THEN** в итоге у траты новые и сумма, и категория

#### Scenario: Очистка комментария
- **WHEN** передаётся пустой комментарий
- **THEN** комментарий траты становится пустым, остальные поля не меняются

## ADDED Requirements

### Requirement: Страница трат члена семьи
Список трат в пределах одного члена семьи SHALL возвращать страницу, количество и сумму по тем же правилам, что и общий список, но только по тратам этого члена семьи; условие «член семьи» из фильтра заменяется на переданный `user_id`.

#### Scenario: Страница своих трат
- **WHEN** у члена семьи `A` 45 трат, у `B` ещё 10, запрашивается список `A` с лимитом 30 и смещением 30
- **THEN** страница содержит 15 трат `A`, количество равно `45`, сумма равна сумме трат `A`

#### Scenario: Чужой фильтр игнорируется
- **WHEN** член семьи `A` запрашивает список с условием «член семьи `B`»
- **THEN** в странице, количестве и сумме учитываются только траты `A`

### Requirement: Страница и итоги списка трат
Список трат SHALL возвращать страницу, заданную лимитом и смещением, вместе с количеством всех трат под условия и их суммарной суммой. Количество и сумма SHALL считаться в хранилище без учёта лимита и смещения.

#### Scenario: Лимит и смещение
- **WHEN** под условия подходят 45 трат, запрашивается лимит 30 со смещением 30
- **THEN** страница содержит 15 трат (с 31-й по 45-ю), количество равно `45`, сумма равна сумме всех 45 трат

#### Scenario: Смещение за пределами выборки
- **WHEN** под условия подходят 10 трат, запрашивается смещение 100
- **THEN** страница пуста, количество равно `10`, сумма равна сумме всех 10 трат
