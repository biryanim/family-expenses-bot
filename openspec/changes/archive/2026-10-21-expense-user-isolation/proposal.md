# Proposal

## Why

Механизм изоляции трат в боте уже есть после `expense-agent`. `user_id` приходит из Telegram-апдейта и передаётся в инструменты кодом. В схемах инструментов нет параметра пользователя, лишние поля аргументов отклоняются. SQL всегда фильтрует по `user_id`. Но каждый слой проверен только по отдельности, на моках соседнего слоя. Ни один тест не прогоняет промпт-инъекцию через всю цепочку «модель → агент → инструменты → usecase → репозиторий». Никто не проверяет и то, что ответ на чужой `id` неотличим от ответа на несуществующий. Кроме того, системный промпт ничего не говорит о запросах про других пользователей. На «покажи траты пользователя 123» модель может показать собственные траты отправителя и подать их как чужие. Утечки здесь нет, но ответ вводит в заблуждение.

## What Changes

- Сквозные тесты изоляции через настоящие агент, инструменты и usecase. Модель и репозиторий подменяются моками. Сценарии:
  - mock-LLM вызывает инструменты с чужим `user_id` в аргументах и с `id` чужой траты;
  - пользователь A не видит, не меняет и не удаляет траты пользователя B;
  - в репозиторий не уходит ни одно обращение с `user_id`, отличным от отправителя.
- Тесты неразличимости: для каждого инструмента, принимающего `id` (`update_expense`, `delete_expense`), результат для чужой траты побайтно совпадает с результатом для несуществующей.
- В системный промпт добавляется правило: агент работает только с тратами отправителя. На просьбы о тратах другого пользователя он отвечает, что показывает только траты самого пишущего, и не выдаёт его траты за чужие.
- Переименование тестов репозитория с испорченными именами (`TestUpdateExpenseForUser_6OTFOUND`, `TestDeleteExpenseForUser_2OTFOUND` и аналогичных) в `_NotFound`.
- Логика изоляции в `usecase`, `repository` и `transport/telegram` не меняется. Её корректность подтверждают новые тесты.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `expense-agent`: требование «Пользователь задаётся кодом» дополняется сценариями сквозной промпт-инъекции и неразличимости чужой и несуществующей траты. Добавляется требование о том, как агент отвечает на запросы о тратах других пользователей.

## Impact

- `internal/agent/agent.go`: новое правило в системном промпте.
- `internal/agent/agent_test.go`, `internal/agent/handle_message_test.go`: сквозные тесты с настоящими `tools` и `usecase` и моком `ExpenseRepository`, включая тесты неразличимости по содержимому tool-сообщений, которые получает модель.
- `internal/database/repository/*_test.go`: переименование тестов.
- API, схема БД, зависимости и конфиг не меняются. Тесты с настоящим PostgreSQL сознательно не добавляются: изоляция на уровне SQL по-прежнему проверяется по тексту запроса и аргументам в моке пула.
