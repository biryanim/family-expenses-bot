# web-panel Specification

## Purpose

Определяет веб-панель главы семьи: откуда она берёт адрес REST API, как показывает траты всех членов семьи с фильтрами и как через REST API создаёт, изменяет и удаляет траты.

## Requirements

### Requirement: Адрес API из конфигурации
Панель SHALL обращаться к REST API по базовому адресу из конфигурации сборки. Если адрес не задан, используется относительный путь `/api`. Адрес бэкенда SHALL NOT быть записан в исходном коде панели.

#### Scenario: Адрес по умолчанию
- **WHEN** панель собрана без заданного адреса API и открыта в браузере
- **THEN** запросы к API уходят на `/api/...` того же origin, с которого открыта панель

#### Scenario: Адрес задан при сборке
- **WHEN** панель собрана с базовым адресом `https://example.test/api`
- **THEN** список трат запрашивается с `https://example.test/api/expenses`

### Requirement: Отдача статики и проксирование API
Собранная панель SHALL отдаваться веб-сервером, который проксирует запросы на `/api/` к бэкенду, адрес которого задаётся переменной окружения контейнера при запуске, без пересборки образа. Остальные пути SHALL отдавать статику панели.

#### Scenario: Запрос к API через веб-сервер панели
- **WHEN** контейнер панели запущен с адресом бэкенда `http://app:8080`, и браузер запрашивает `/api/members`
- **THEN** запрос передаётся на `http://app:8080/api/members`, браузер получает ответ бэкенда

#### Scenario: Смена адреса бэкенда
- **WHEN** тот же образ запускается с другим адресом бэкенда
- **THEN** запросы к `/api/` уходят на новый адрес без пересборки образа

#### Scenario: Главная страница
- **WHEN** браузер открывает `/`
- **THEN** отдаётся страница панели

### Requirement: Доступ без авторизации
Панель SHALL открываться и выполнять все операции без входа и без передачи учётных данных.

#### Scenario: Открытие панели
- **WHEN** глава семьи открывает панель в браузере
- **THEN** сразу отображается список трат, форма входа не показывается

### Requirement: Список трат всех членов семьи
Панель SHALL показывать таблицу трат, полученную из `GET /expenses`, в порядке ответа API. В строке: владелец, сумма, категория, дата и время траты, комментарий.

#### Scenario: Траты двух членов семьи
- **WHEN** в API есть траты членов семьи `123` и `456`, фильтры не заданы
- **THEN** в таблице есть траты обоих в том же порядке, что в ответе API

### Requirement: Владелец по имени
Владелец траты SHALL отображаться по данным `GET /members`: имя и фамилия, если они есть, иначе `@username`, иначе Telegram ID. Если члена семьи нет в ответе `GET /members`, отображается его Telegram ID.

#### Scenario: Член семьи без фамилии
- **WHEN** у члена семьи `first_name` = `Анна`, `last_name` = `""`
- **THEN** владелец его трат отображается как `Анна`

#### Scenario: Неизвестный член семьи
- **WHEN** у траты `user_id` = `789`, а в списке членов семьи такого нет
- **THEN** владелец отображается как `789`

### Requirement: Сумма в рублях
Сумма SHALL отображаться в рублях с копейками через запятую и знаком `₽`, разряды разделены пробелом. Перевод из копеек SHALL выполняться целочисленной арифметикой, без дробных чисел.

#### Scenario: Целые рубли
- **WHEN** `amount` = `120000`
- **THEN** отображается `1 200,00 ₽`

#### Scenario: Копейки
- **WHEN** `amount` = `35050`
- **THEN** отображается `350,50 ₽`

### Requirement: Категории по-русски
Категории SHALL отображаться и выбираться по-русски: `food` — еда, `transport` — транспорт, `housing` — жильё, `entertainment` — развлечения, `health` — здоровье, `shopping` — покупки, `other` — другое. В API SHALL передаваться код категории.

#### Scenario: Отображение категории
- **WHEN** у траты `category` = `housing`
- **THEN** в таблице отображается `жильё`

### Requirement: Фильтры списка
Панель SHALL предоставлять фильтры по члену семьи, периоду (дата начала, дата конца) и категории. Заданные фильтры SHALL передаваться в `GET /expenses` одновременно как `user_id`, `from`, `to`, `category`; незаданный фильтр не передаётся. Таблица SHALL показывать ровно то, что вернул API.

#### Scenario: Комбинация фильтров
- **WHEN** выбраны член семьи `123` и категория «еда»
- **THEN** панель запрашивает `GET /expenses?user_id=123&category=food` и показывает ровно траты из ответа

#### Scenario: Сброс фильтра
- **WHEN** фильтр по категории сбрасывается в «все»
- **THEN** параметр `category` не передаётся в запросе

### Requirement: Границы периода
Даты периода SHALL трактоваться в часовом поясе браузера, обе включительно: `from` — начало дня даты начала, `to` — начало дня, следующего за датой конца. Если дата начала позже даты конца, панель SHALL показать ошибку у фильтра и не отправлять запрос.

#### Scenario: Период в одну неделю
- **WHEN** в браузере с часовым поясом UTC+3 выбран период с 1 по 7 октября 2026
- **THEN** запрос содержит `from` = `2026-10-01T00:00:00+03:00` и `to` = `2026-10-08T00:00:00+03:00`

#### Scenario: Перевёрнутый период
- **WHEN** дата начала 10 октября, дата конца 1 октября
- **THEN** у фильтра показана ошибка, запрос с этими параметрами не отправляется

### Requirement: Фильтры в адресе страницы
Текущие фильтры SHALL отражаться в query-строке адреса панели и восстанавливаться из неё при открытии страницы.

#### Scenario: Перезагрузка страницы
- **WHEN** выбраны фильтры и страница перезагружена
- **THEN** те же фильтры выбраны, и список запрошен с ними

### Requirement: Состояния списка
Панель SHALL явно показывать состояние загрузки, пустой результат и ошибку запроса списка. Пустой результат SHALL отличаться от ошибки. При ошибке SHALL быть доступен повтор запроса.

#### Scenario: Загрузка
- **WHEN** ответ `GET /expenses` ещё не получен
- **THEN** показан индикатор загрузки

#### Scenario: Пусто
- **WHEN** API вернул пустой массив
- **THEN** показано сообщение, что трат по выбранным фильтрам нет

#### Scenario: Ошибка
- **WHEN** API ответил 500 или недоступен
- **THEN** показано сообщение об ошибке и кнопка повтора, таблица не показывается

### Requirement: Показ ошибок API
При ответе API в формате `{"code", "message"}` панель SHALL показывать понятное по-русски сообщение по `code`; для неизвестного кода — `message` из ответа. При сетевой ошибке или ответе не в этом формате панель SHALL показывать общее сообщение о недоступности сервера.

#### Scenario: Неизвестный член семьи
- **WHEN** `POST /expenses` вернул 400 с `code` = `unknown_member`
- **THEN** пользователь видит сообщение, что такого члена семьи нет

#### Scenario: Сервер недоступен
- **WHEN** бэкенд не отвечает
- **THEN** пользователь видит сообщение, что сервер недоступен

### Requirement: Ввод суммы
Поле суммы SHALL принимать рубли: целое число или число с одним-двумя знаками после запятой или точки, пробелы игнорируются. Значение SHALL переводиться в копейки без дробной арифметики. Пустое, нулевое, отрицательное значение, больше двух знаков после разделителя или не число SHALL давать ошибку у поля без отправки запроса.

#### Scenario: Сумма с копейками
- **WHEN** введено `350,5`
- **THEN** в API передаётся `amount` = `35050`

#### Scenario: Сумма с пробелами
- **WHEN** введено `1 200`
- **THEN** в API передаётся `amount` = `120000`

#### Scenario: Некорректная сумма
- **WHEN** введено `0`, `-5`, `12,345` или `abc`
- **THEN** у поля показана ошибка, запрос не отправляется

### Requirement: Создание траты
Панель SHALL позволять создать трату через `POST /expenses`: владелец из списка членов семьи, сумма, категория (обязательные), дата и время (по умолчанию текущий момент) и комментарий. Если членов семьи нет, панель SHALL сообщить, что сначала нужно написать боту, и не давать отправить форму.

#### Scenario: Успешное создание
- **WHEN** выбран член семьи `123`, введены сумма `350`, категория «еда», комментарий `кофе`, и форма отправлена
- **THEN** выполняется `POST /expenses` с `user_id` = `123`, `amount` = `35000`, `category` = `food`, `comment` = `кофе`, форма закрывается, трата видна в списке, если подходит под фильтры

#### Scenario: Нет членов семьи
- **WHEN** `GET /members` вернул пустой массив
- **THEN** форма создания сообщает, что членов семьи нет, отправка недоступна

#### Scenario: Не заполнены обязательные поля
- **WHEN** форма отправляется без владельца или без суммы
- **THEN** у пустых полей показаны ошибки, запрос не отправляется

### Requirement: Правка траты
Панель SHALL позволять изменить сумму, категорию, дату и время и комментарий траты через `PUT /expenses/{id}`. Форма SHALL открываться с текущими значениями траты. Владелец показывается, но не редактируется.

#### Scenario: Изменение суммы
- **WHEN** у траты на `350,00 ₽` в форме правки сумма меняется на `450` и форма отправляется
- **THEN** выполняется `PUT` с `amount` = `45000` и прежними категорией, датой и комментарием, в списке сумма `450,00 ₽`

#### Scenario: Трата уже удалена
- **WHEN** трата удалена ботом, а в панели отправлена её правка
- **THEN** API отвечает 404, панель сообщает, что трата не найдена, и обновляет список

### Requirement: Удаление с подтверждением
Панель SHALL удалять трату через `DELETE /expenses/{id}` только после подтверждения пользователем. Отказ от подтверждения SHALL NOT отправлять запрос.

#### Scenario: Подтверждённое удаление
- **WHEN** пользователь нажимает «удалить» у траты и подтверждает
- **THEN** выполняется `DELETE`, трата исчезает из списка

#### Scenario: Отмена
- **WHEN** пользователь нажимает «удалить» и отменяет подтверждение
- **THEN** запрос не отправляется, трата остаётся

### Requirement: Обновление списка после операции
После успешного создания, правки или удаления панель SHALL перезапросить список трат с текущими фильтрами. Фильтры SHALL NOT сбрасываться.

#### Scenario: Удаление при включённом фильтре
- **WHEN** выбран фильтр «транспорт», и удаляется одна из трат
- **THEN** список перезапрашивается с `category` = `transport`, фильтр остаётся выбранным

### Requirement: Актуальность данных из бота
Панель и бот SHALL работать с одними данными через REST API. Траты, изменённые ботом, SHALL появляться в панели при возврате на вкладку панели или по кнопке обновления без перезагрузки страницы.

#### Scenario: Трата добавлена ботом
- **WHEN** панель открыта, член семьи пишет боту `кофе 350`, и глава семьи возвращается на вкладку панели
- **THEN** список перезапрашивается, новая трата видна

#### Scenario: Трата добавлена панелью
- **WHEN** в панели создана трата члена семьи `123` на `350 ₽` с категорией «еда»
- **THEN** член семьи `123` видит её в боте на запрос `покажи траты за сегодня`
