# expense-repository Specification

## Purpose

Определяет слой доступа к тратам, общий для REST API и бота: какие операции над тратами доступны, как фильтруется список, как изолируются траты разных членов семьи и какие ошибки получает вызывающий код.

## Requirements

### Requirement: Создание траты
Слой доступа SHALL сохранять трату с переданными `user_id`, `amount`, `category`, `spent_at` и `comment` и возвращать её с назначенными хранилищем `id` и `created_at`. У новой траты `updated_at` пуст.

#### Scenario: Успешное создание
- **WHEN** создаётся трата члена семьи `A` на `35000` в категории `food` с `spent_at` = `2026-10-17T12:30:00+03:00` и комментарием `кофе`
- **THEN** возвращается трата с ненулевым `id`, заполненным `created_at`, пустым `updated_at` и теми же значениями остальных полей

### Requirement: Доменные ошибки при нарушении ограничений
Если хранилище отклоняет запись из-за неизвестного члена семьи, суммы не больше нуля или недопустимой категории, слой доступа SHALL вернуть соответствующую различимую доменную ошибку: «неизвестный член семьи», «недопустимая сумма», «недопустимая категория». Это касается создания и изменения. Прочие ошибки хранилища возвращаются с контекстом операции.

#### Scenario: Неизвестный член семьи
- **WHEN** создаётся трата с `user_id`, которого нет среди членов семьи
- **THEN** возвращается ошибка «неизвестный член семьи»

#### Scenario: Недопустимая сумма
- **WHEN** создаётся или изменяется трата с `amount` = `0`
- **THEN** возвращается ошибка «недопустимая сумма»

#### Scenario: Недопустимая категория
- **WHEN** создаётся или изменяется трата с категорией `travel`
- **THEN** возвращается ошибка «недопустимая категория»

#### Scenario: Сбой хранилища
- **WHEN** хранилище возвращает ошибку, не связанную с ограничениями (например, обрыв соединения)
- **THEN** возвращается ошибка, которая содержит исходную и название операции и не является ни одной из доменных ошибок

### Requirement: Получение траты по id
Слой доступа SHALL возвращать трату по `id` со всеми полями. Если траты с таким `id` нет, SHALL возвращаться ошибка «трата не найдена».

#### Scenario: Трата существует
- **WHEN** запрашивается трата по `id` существующей траты
- **THEN** возвращается трата со всеми полями, включая `updated_at`, если трата изменялась

#### Scenario: Трата не существует
- **WHEN** запрашивается трата по `id`, которого нет
- **THEN** возвращается ошибка «трата не найдена»

### Requirement: Список трат с фильтрами
Слой доступа SHALL возвращать список трат, отфильтрованный по любой комбинации условий: член семьи, начало периода (включительно), конец периода (не включительно) по `spent_at`, категория. Не заданное условие не ограничивает выборку. Условия объединяются по «И». Порядок — от новых `spent_at` к старым, при равном `spent_at` — от большего `id` к меньшему. Пустой результат — пустой список, не ошибка.

#### Scenario: Без фильтров
- **WHEN** список запрашивается без условий
- **THEN** возвращаются траты всех членов семьи в порядке убывания `spent_at`

#### Scenario: Фильтр по члену семьи
- **WHEN** список запрашивается с условием «член семьи `A`»
- **THEN** возвращаются только траты `A`

#### Scenario: Границы периода
- **WHEN** список запрашивается за период с `2026-10-01T00:00:00+03:00` по `2026-10-08T00:00:00+03:00`
- **THEN** трата ровно в `2026-10-01T00:00:00+03:00` входит в результат, а трата ровно в `2026-10-08T00:00:00+03:00` — нет

#### Scenario: Только одна граница периода
- **WHEN** задано только начало периода (или только конец)
- **THEN** выборка ограничена только с этой стороны

#### Scenario: Фильтр по категории
- **WHEN** список запрашивается с категорией `transport`
- **THEN** возвращаются только траты категории `transport`

#### Scenario: Все фильтры вместе
- **WHEN** заданы член семьи `A`, период и категория `food`
- **THEN** возвращаются только траты `A` категории `food` из этого периода

#### Scenario: Ничего не найдено
- **WHEN** ни одна трата не подходит под условия
- **THEN** возвращается пустой список без ошибки

### Requirement: Изменение траты
Слой доступа SHALL изменять у траты `amount`, `category`, `spent_at` и `comment`, выставлять `updated_at` в текущее время и возвращать изменённую трату. `id`, `user_id` и `created_at` не меняются. Если траты с таким `id` нет, SHALL возвращаться ошибка «трата не найдена», и ничего не меняется.

#### Scenario: Успешное изменение
- **WHEN** у существующей траты меняется сумма на `120000`
- **THEN** возвращается трата с новой суммой и заполненным `updated_at`, а `user_id` и `created_at` прежние

#### Scenario: Повторное изменение
- **WHEN** трата изменяется второй раз
- **THEN** `updated_at` выставляется заново временем этого изменения

#### Scenario: Изменение несуществующей траты
- **WHEN** изменяется трата по `id`, которого нет
- **THEN** возвращается ошибка «трата не найдена»

### Requirement: Удаление траты
Слой доступа SHALL удалять трату по `id`. Если траты с таким `id` нет, SHALL возвращаться ошибка «трата не найдена».

#### Scenario: Успешное удаление
- **WHEN** удаляется существующая трата
- **THEN** ошибки нет, и трата больше не возвращается ни по `id`, ни в списке

#### Scenario: Удаление несуществующей траты
- **WHEN** удаляется трата по `id`, которого нет
- **THEN** возвращается ошибка «трата не найдена»

### Requirement: Операции в пределах одного члена семьи
Слой доступа SHALL предоставлять получение, список, изменение и удаление трат с обязательным `user_id`. Эти операции затрагивают только траты этого члена семьи. Чужая трата для них ведёт себя как несуществующая: «трата не найдена», в списке её нет, изменения и удаления не происходит. Условие «член семьи» из фильтра в этих операциях заменяется на переданный `user_id`.

#### Scenario: A не видит трату B
- **WHEN** член семьи `A` запрашивает по `id` трату члена семьи `B`
- **THEN** возвращается ошибка «трата не найдена»

#### Scenario: A не получает траты B в списке
- **WHEN** член семьи `A` запрашивает свой список, в том числе с фильтром, где указан член семьи `B`
- **THEN** в результате только траты `A`

#### Scenario: A не меняет трату B
- **WHEN** член семьи `A` изменяет трату члена семьи `B`
- **THEN** возвращается ошибка «трата не найдена», трата `B` не меняется

#### Scenario: A не удаляет трату B
- **WHEN** член семьи `A` удаляет трату члена семьи `B`
- **THEN** возвращается ошибка «трата не найдена», трата `B` остаётся

#### Scenario: A работает со своей тратой
- **WHEN** член семьи `A` получает, изменяет или удаляет свою трату
- **THEN** операция выполняется так же, как без ограничения по члену семьи

### Requirement: Список известных членов семьи
Слой доступа SHALL возвращать список `user_id` всех членов семьи, записанных в хранилище, по возрастанию, включая членов семьи без трат. Если членов семьи нет, возвращается пустой список.

#### Scenario: Члены семьи с тратами и без
- **WHEN** в хранилище есть члены семьи `100` (с тратами) и `50` (без трат)
- **THEN** возвращается `[50, 100]`

#### Scenario: Нет членов семьи
- **WHEN** в хранилище нет ни одного члена семьи
- **THEN** возвращается пустой список без ошибки
