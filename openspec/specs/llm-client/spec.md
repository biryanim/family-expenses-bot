# llm-client Specification

## Purpose

Определяет, как приложение обращается к OpenAI-совместимой языковой модели с tool calling: как выбираются провайдер и модель, что возвращается вызывающему коду, сколько он ждёт ответа и как ведёт себя при ошибках провайдера.

## Requirements

### Requirement: Провайдер и модель задаются только конфигом
Клиент LLM SHALL отправлять запросы Chat Completions на адрес из `LLM_BASE_URL` с ключом из `LLM_API_KEY` и моделью из `LLM_MODEL`. Смена провайдера (OpenAI, OpenRouter и другие OpenAI-совместимые) или модели SHALL NOT требовать изменений кода.

#### Scenario: Запрос уходит на настроенный адрес
- **WHEN** `LLM_BASE_URL=http://127.0.0.1:9999/v1`, `LLM_MODEL=test-model`, и клиент выполняет запрос
- **THEN** HTTP-запрос приходит на `http://127.0.0.1:9999/v1/chat/completions`, в теле `model` равно `test-model`, в заголовке `Authorization` — `Bearer <LLM_API_KEY>`

#### Scenario: Смена провайдера
- **WHEN** в `.env` меняются только `LLM_BASE_URL`, `LLM_API_KEY` и `LLM_MODEL` на значения другого OpenAI-совместимого провайдера
- **THEN** после перезапуска приложение обращается к новому провайдеру без пересборки с изменённым кодом

### Requirement: Передача истории и инструментов
Клиент LLM SHALL отправлять модели историю диалога из сообщений с ролями system, user, assistant (с текстом и/или вызовами инструментов) и tool (результат вызова с идентификатором вызова), а также список инструментов с именем, описанием и JSON Schema параметров.

#### Scenario: Инструменты в запросе
- **WHEN** клиент вызывается с одним инструментом `add_expense` и его схемой параметров
- **THEN** в теле запроса `tools` содержит один элемент типа `function` с этим именем, описанием и схемой

#### Scenario: Результат инструмента в истории
- **WHEN** история содержит ответ ассистента с вызовом инструмента `call_1` и сообщение tool с результатом для `call_1`
- **THEN** в теле запроса сообщение ассистента содержит `tool_calls` с `id` `call_1`, а следующее сообщение имеет роль `tool` и `tool_call_id` `call_1`

#### Scenario: Запрос без инструментов
- **WHEN** клиент вызывается с пустым списком инструментов
- **THEN** в теле запроса нет поля `tools`

### Requirement: Разбор ответа модели
Клиент LLM SHALL возвращать сообщение ассистента из первого варианта ответа: текст и список вызовов инструментов, у каждого — идентификатор, имя инструмента и аргументы строкой JSON. Пустые аргументы SHALL возвращаться как `{}`.

#### Scenario: Ответ с вызовом инструмента
- **WHEN** модель отвечает `tool_calls` с `id` `call_1`, `function.name` `add_expense` и `function.arguments` `{"amount":350}`
- **THEN** клиент возвращает один вызов с идентификатором `call_1`, именем `add_expense` и аргументами `{"amount":350}`

#### Scenario: Ответ текстом
- **WHEN** модель отвечает текстом без `tool_calls`
- **THEN** клиент возвращает этот текст и пустой список вызовов

#### Scenario: Пустые аргументы
- **WHEN** модель вызывает инструмент с `function.arguments` равным пустой строке
- **THEN** аргументы вызова возвращаются как `{}`

#### Scenario: Ответ без вариантов
- **WHEN** провайдер отвечает 200 с пустым `choices`
- **THEN** клиент возвращает ошибку, а не пустое сообщение

### Requirement: Повторы при временных сбоях провайдера
Клиент LLM SHALL повторять запрос не более 2 раз при сетевых ошибках и ответах 408, 409, 429 и 5xx. Ответы 400, 401, 403, 404 и 422 SHALL NOT повторяться.

#### Scenario: Временный сбой
- **WHEN** провайдер дважды отвечает 503, а на третий запрос — 200
- **THEN** клиент возвращает разобранный ответ, всего отправлено 3 запроса

#### Scenario: Постоянный сбой
- **WHEN** провайдер на каждый запрос отвечает 503
- **THEN** клиент возвращает ошибку после 3 запросов

#### Scenario: Неверный ключ
- **WHEN** провайдер отвечает 401
- **THEN** клиент возвращает ошибку после одного запроса

### Requirement: Ограничение времени ожидания
Каждый вызов клиента LLM SHALL завершаться не позже чем через `LLM_TIMEOUT` с момента начала, включая все повторы. При истечении срока клиент SHALL вернуть ошибку, распознаваемую как истечение срока контекста (`context.DeadlineExceeded`). Отмена контекста вызывающим SHALL прерывать запрос.

#### Scenario: Модель не успела ответить
- **WHEN** `LLM_TIMEOUT=1s`, а провайдер не отвечает 5 секунд
- **THEN** клиент возвращает ошибку примерно через 1 секунду, и `errors.Is(err, context.DeadlineExceeded)` истинно

#### Scenario: Отмена вызывающим
- **WHEN** контекст вызывающего отменён во время ожидания ответа
- **THEN** клиент сразу возвращает ошибку, и `errors.Is(err, context.Canceled)` истинно

### Requirement: Ошибки провайдера без падения и без секретов
При ошибке провайдера, сети или разбора ответа клиент LLM SHALL вернуть ошибку вызывающему, не паникуя. Текст ошибки SHALL содержать HTTP-статус ответа провайдера, если он был, и SHALL NOT содержать значение `LLM_API_KEY`.

#### Scenario: Ошибка провайдера
- **WHEN** провайдер отвечает 401 с телом, где упомянут переданный ключ
- **THEN** клиент возвращает ошибку, в тексте которой есть `401`, но нет значения ключа

#### Scenario: Некорректный ответ
- **WHEN** провайдер отвечает 200 с телом, не являющимся JSON
- **THEN** клиент возвращает ошибку, процесс продолжает работу

### Requirement: Проверка на реальной модели
Проект SHALL содержать команду ручной проверки, которая с конфигом из окружения отправляет настроенной модели запрос с одним тестовым инструментом и печатает разобранные вызовы инструментов или ошибку. Значение `LLM_API_KEY` SHALL NOT выводиться.

#### Scenario: Модель вызывает инструмент
- **WHEN** в `.env` заданы рабочие `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, и запускается команда проверки
- **THEN** выводится как минимум один вызов тестового инструмента с идентификатором, именем и аргументами-JSON, процесс завершается с кодом 0

#### Scenario: Модель не вызвала инструмент
- **WHEN** модель ответила текстом без вызова инструмента или вернула ошибку
- **THEN** команда выводит текст ответа или ошибку и завершается с ненулевым кодом
