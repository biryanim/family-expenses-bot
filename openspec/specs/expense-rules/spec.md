# expense-rules Specification

## Purpose

Определяет бизнес-правила трат, которые применяются до обращения к хранилищу и одинаковы для REST API и Telegram-бота: какие сумма, категория и дата допустимы, какая дата ставится по умолчанию и какие доменные ошибки получает вызывающий код.

## Requirements

### Requirement: Сумма траты положительна
При создании и изменении траты сумма SHALL быть целым числом копеек больше нуля. Иначе операция SHALL завершиться ошибкой «недопустимая сумма» без обращения к хранилищу.

#### Scenario: Нулевая сумма
- **WHEN** создаётся или изменяется трата с суммой `0`
- **THEN** возвращается ошибка «недопустимая сумма», трата не сохраняется

#### Scenario: Отрицательная сумма
- **WHEN** создаётся трата с суммой `-100`
- **THEN** возвращается ошибка «недопустимая сумма»

#### Scenario: Минимальная сумма
- **WHEN** создаётся трата с суммой `1`
- **THEN** трата сохраняется

### Requirement: Категория из фиксированного списка
При создании и изменении траты, а также в фильтре списка категория SHALL быть одним из кодов `food`, `transport`, `housing`, `entertainment`, `health`, `shopping`, `other`. Иначе операция SHALL завершиться ошибкой «недопустимая категория». Пустая категория в фильтре означает «без ограничения».

#### Scenario: Неизвестная категория при создании
- **WHEN** создаётся трата с категорией `travel` или пустой категорией
- **THEN** возвращается ошибка «недопустимая категория», трата не сохраняется

#### Scenario: Неизвестная категория в фильтре
- **WHEN** список запрашивается с категорией `travel`
- **THEN** возвращается ошибка «недопустимая категория»

#### Scenario: Фильтр без категории
- **WHEN** список запрашивается без категории
- **THEN** выборка по категории не ограничивается

### Requirement: Дата траты по умолчанию
Если при создании траты дата не задана, трате SHALL назначаться текущий момент.

#### Scenario: Создание без даты
- **WHEN** создаётся трата без даты в момент `2026-10-18T10:00:00+03:00`
- **THEN** сохраняется трата со `spent_at` = `2026-10-18T10:00:00+03:00`

#### Scenario: Создание с датой
- **WHEN** создаётся трата с датой `2026-10-17T09:00:00+03:00`
- **THEN** сохраняется трата с этой датой

### Requirement: Дата траты при изменении обязательна
При изменении траты дата SHALL быть задана. Если дата не задана, операция SHALL завершиться ошибкой «некорректная дата» без обращения к хранилищу.

#### Scenario: Изменение без даты
- **WHEN** изменяется трата без даты
- **THEN** возвращается ошибка «некорректная дата», трата не меняется

### Requirement: Корректный период фильтра
Если в фильтре списка заданы и начало, и конец периода, начало SHALL быть не позже конца. Иначе SHALL возвращаться ошибка «некорректная дата». Совпадающие начало и конец допустимы и дают пустой результат.

#### Scenario: Начало позже конца
- **WHEN** список запрашивается с началом `2026-10-08T00:00:00+03:00` и концом `2026-10-01T00:00:00+03:00`
- **THEN** возвращается ошибка «некорректная дата»

#### Scenario: Совпадающие границы
- **WHEN** начало и конец периода равны
- **THEN** возвращается пустой список без ошибки

### Requirement: Различимые доменные ошибки
Нарушения правил SHALL возвращаться различимыми доменными ошибками: «недопустимая сумма», «недопустимая категория», «некорректная дата», «неизвестный член семьи», «трата не найдена». Ошибки хранилища, не являющиеся доменными, SHALL передаваться вызывающему коду без превращения в доменные.

#### Scenario: Трата не найдена
- **WHEN** запрашивается, изменяется или удаляется трата с несуществующим `id`
- **THEN** возвращается ошибка «трата не найдена»

#### Scenario: Неизвестный член семьи
- **WHEN** создаётся трата для `user_id`, которого нет среди членов семьи
- **THEN** возвращается ошибка «неизвестный член семьи»

#### Scenario: Сбой хранилища
- **WHEN** хранилище возвращает ошибку соединения
- **THEN** возвращается ошибка, которая не является ни одной из доменных

### Requirement: Правила для операций одного члена семьи
Получение, список, изменение и удаление трат в пределах одного члена семьи SHALL проверять сумму, категорию, дату изменения, длину комментария, период фильтра и параметры страницы по тем же правилам и с теми же доменными ошибками, что и общие операции. Чужая трата SHALL давать ошибку «трата не найдена».

#### Scenario: Изменение своей траты с нулевой суммой
- **WHEN** член семьи `A` изменяет свою трату, указав сумму `0`
- **THEN** возвращается ошибка «недопустимая сумма», трата не меняется

#### Scenario: Список своих трат с неверным периодом
- **WHEN** член семьи `A` запрашивает свой список с началом позже конца
- **THEN** возвращается ошибка «некорректная дата»

#### Scenario: Изменение чужой траты
- **WHEN** член семьи `A` изменяет трату члена семьи `B` с корректными полями
- **THEN** возвращается ошибка «трата не найдена»

### Requirement: Последняя трата члена семьи
Последней тратой члена семьи SHALL считаться его трата, добавленная позже всех остальных, независимо от даты траты. Если трат нет, SHALL возвращаться ошибка «трата не найдена». Траты других членов семьи не учитываются.

#### Scenario: Последняя добавленная
- **WHEN** член семьи `A` добавил трату с датой сегодня, затем трату с датой вчера
- **THEN** последней считается трата с датой вчера

#### Scenario: Чужая трата добавлена позже
- **WHEN** член семьи `A` добавил трату, затем член семьи `B` добавил свою
- **THEN** последняя трата `A` — его собственная

#### Scenario: Нет трат
- **WHEN** у члена семьи нет ни одной траты
- **THEN** возвращается ошибка «трата не найдена»

### Requirement: Параметры страницы
Лимит страницы SHALL быть целым от 1 до 500, смещение — целым не меньше 0. Иначе SHALL возвращаться ошибка «некорректная страница». Проверка выполняется до обращения к хранилищу.

#### Scenario: Лимит вне диапазона
- **WHEN** список запрашивается с лимитом `0` или `501`
- **THEN** возвращается ошибка «некорректная страница», хранилище не вызывается

#### Scenario: Отрицательное смещение
- **WHEN** список запрашивается со смещением `-1`
- **THEN** возвращается ошибка «некорректная страница»

#### Scenario: Граничные значения
- **WHEN** список запрашивается с лимитом `500` и смещением `0`
- **THEN** ошибки нет

### Requirement: Длина комментария
Комментарий траты SHALL сохраняться без пробелов по краям и содержать после этого не более 200 символов (рун). Иначе при создании и изменении SHALL возвращаться ошибка «недопустимый комментарий», и ничего не сохраняется.

#### Scenario: 201 символ
- **WHEN** создаётся трата с комментарием из 201 символа
- **THEN** возвращается ошибка «недопустимый комментарий»

#### Scenario: 200 символов
- **WHEN** создаётся трата с комментарием из 200 кириллических символов
- **THEN** трата создаётся

#### Scenario: Пробелы по краям
- **WHEN** создаётся трата с комментарием из 200 символов, окружённым пробелами
- **THEN** трата создаётся, комментарий сохранён без пробелов по краям

#### Scenario: Изменение комментария
- **WHEN** у существующей траты комментарий меняется на строку из 201 символа
- **THEN** возвращается ошибка «недопустимый комментарий», трата не меняется
